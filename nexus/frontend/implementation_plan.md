## 1. Product Philosophy

NEXUS is not a chat wrapper, a dashboard, or a project manager. It is an **AI-Powered Research Operating System**.

### Core Beliefs
1. **Evidence Before Execution**: Software failure is rarely a failure of coding capability; it is a failure of baseline assumptions. NEXUS turns speculative ideas into evidence-backed architecture before a single line of production code is written.
2. **Cognitive Co-pilot, Not Generator**: Code generators treat code as cheap disposable text. NEXUS treats research and architecture as non-linear graph topologies, empowering engineers and founders to reason at the highest abstraction layer.
3. **Information Density with Zero Visual Noise**: High-density engineering tools often degrade into clunky tabular spreadsheets. NEXUS merges high-density scientific graphs with spatial clarity, deep dark aesthetics, glassmorphism, and responsive depth.
4. **Cinematic Spatial Flow**: Software documentation should not be passive reading. Exploring a project roadmap should feel like walking through an interactive, live-updating intelligence facility.

## 2. Brand Personality

### Personality Archetypes
- **The Intelligence Lab (70%)**: Authoritative, precise, analytical, evidence-grounded (Arxiv, Google Scholar, GitHub graph engine).
- **The Futuristic Studio (30%)**: Sleek, mysterious, tactile, premium, aesthetic mastery (Apple, Linear, Arc Browser, Stripe).

### Tone of Voice & Microcopy Rules
- **Direct & Uncompromising**: No hyperbole, no "AI magic" buzzwords. Use scientific and systems-engineering terms: *Topology, Synthesis, Verification Vector, Architectural Drift, Gap Analysis*.
- **Precise Statements**: 
  - *Avoid*: "Supercharge your app idea with fast AI!"
  - *Prefer*: "Synthesize 400 paper citations into a zero-drift system dependency graph in 42 seconds."

## 3. User Psychology & Emotional Trajectory

The experience maps directly to a 6-stage cognitive conversion model:

```
[Curiosity] ──► [Interest] ──► [Understanding] ──► [Trust] ──► [Excitement] ──► [Conversion]
  Scene 1         Scene 2          Scene 3-5       Scene 6-8       Scene 9         Scene 10
```

1. **Curiosity ("What is this?")**: Triggered by Scene 1 (Massive ambient hero with live research node particle graph & command palette).
2. **Interest ("This looks different")**: Triggered by Scene 2 (Narrative transition: Idea -> Assumption -> Evidence -> Architecture -> Roadmap).
3. **Understanding ("Now I see what it does")**: Triggered by Scenes 3 & 4 (Interactive Timeline & Live Workspace Simulation).
4. **Trust ("This team understands research")**: Triggered by Scenes 5, 6 & 8 (Interactive Evidence Engine, Live System Architecture Canvas, Multi-Source Integration).
5. **Excitement ("I need this for my stack")**: Triggered by Scenes 7 & 9 (Side-by-side workflow contrast & connected developer ecosystem).
6. **Conversion ("I am initializing my workspace")**: Triggered by Scene 10 (Interactive command line CTA & workspace launcher).

## 9. Detailed UX Reasoning for Every Scene

1. **Scene 1 (Hero)**: Minimal text prevents cognitive overload; live WebGL graph instantly communicates "Scientific Tooling" rather than "Standard Marketing SaaS".
2. **Scene 2 (Entropy Story)**: Pinned scroll storytelling converts passive readers into active observers. Morphing words trigger conceptual understanding without requiring paragraph reading.
3. **Scene 3 (Timeline)**: Expanding active flex cards provide progressive disclosure: simple step high-level view by default, dense telemetry data on user engagement.
4. **Scene 4 (Workspace)**: Mock screenshots look static and cheap. A live interactive HTML/CSS UI simulation allows users to feel the tactile responsiveness before signing up.
5. **Scene 5 (Evidence Graph)**: Graph structures prove that NEXUS isn't a sequential linear chat, but an interconnected network of verified research nodes.
6. **Scene 6 (Architecture Builder)**: 3D perspective transitions showcase the transition from high-level visual design down to precise implementation specs.
7. **Scene 7 (Comparison)**: Direct visual contrast eliminates doubt by comparing painful conventional developer friction with NEXUS efficiency.
8. **Scene 8 (Multi-Source Matrix)**: Visualizing authoritative logos (Arxiv, GitHub, Scholar) grounds NEXUS in legitimized research infrastructure.
9. **Scene 9 (Ecosystem)**: Demonstrates workflow longevity—reassuring engineers that NEXUS fits existing tools (VS Code, CLI, GitHub Actions).
10. **Scene 10 (Terminal CTA)**: Engineering users prefer command-line interfaces. Prompting for an email inside an interactive terminal box feels authentic to their daily routine.

## 10. Motion Design System

### Motion Principles
1. **Purposeful Kinetic Physics**: All movement must simulate physical mass, inertia, and spring tension (no rigid linear transitions).
2. **Scroll Choreography**: Scroll position strictly drives animation progress (`scrub: 1` in GSAP terms).

### Motion Tokens & Physics Spring Constants
- **Fast Micro-interaction (Buttons, Links)**:  
  `duration: 0.2s, ease: cubic-bezier(0.16, 1, 0.3, 1)`
- **Spatial Panel Transitions (Tabs, Cards)**:  
  `duration: 0.5s, ease: cubic-bezier(0.25, 1, 0.5, 1)`
- **Scroll Pin Stage Reveals**:  
  `duration: 1.0s, ease: none` (Direct scrub mapping)
- **Spring Physics (Nodes, 3D Canvas)**:  
  `stiffness: 170, damping: 26, mass: 1`

## 21. Accessibility Strategy (WCAG 2.1 AA Compliance)

1. **Contrast Ratios**: All text meets WCAG AA minimum 4.5:1 ratio (white `#F8FAFC` on `#050609` yields 18.2:1 contrast).
2. **Motion Preference**: Full support for `@media (prefers-reduced-motion: reduce)`. When enabled, scroll pinning and 3D transforms turn off in favor of clean fade transitions.
3. **Screen Reader Landmarks**: All scenes use semantic HTML5 tags (`<header>`, `<nav>`, `<main>`, `<section>`, `<footer>`, `<aside>`).
4. **Keyboard Focus**: Visible high-contrast focus rings (`outline: 2px solid var(--accent-cyan)`).

## 22. Performance Strategy (Target: 60 FPS Scroll & 95+ Lighthouse Score)

1. **GPU Offloading**: All animations use `transform: translate3d()` and `opacity` properties to prevent DOM layout repaints.
2. **Canvas Optimizations**: WebGL renderer utilizes OffscreenCanvas where supported and caps pixel density at `Math.min(window.devicePixelRatio, 2)`.
3. **Asset Optimization**: Zero raster image heavy assets; vector SVG icons, dynamic shaders, and code-based typography only.

## 23. Future Scalability Plan

1. **Modular Scene Extensions**: Scenes are isolated independent components, allowing new product feature releases to be plugged in as standalone scenes without refactoring overall scroll logic.
2. **Theme System Readiness**: Color tokens engineered to support light high-contrast lab mode (`--bg-void: #FAFAFC`, `--text-primary: #0F172A`) via CSS variable swaps.
